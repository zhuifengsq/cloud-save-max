# 默认账号唯一性与资料更新时间修复

本轮修复两个已复现问题：并发切换默认账号可能提交两个默认标记；资料刷新失败却显示新资料更新时间。测试只使用临时数据库、假凭据和模拟网盘请求，未操作真实库、未提交代码。

## 默认账号

`drive_accounts` 增加部分唯一索引 `uq_drive_accounts_single_default`，只约束 `is_default=true` 的记录，保证全局最多一个默认账号；允许没有默认账号，保留现有启用账号回退选择逻辑。

切换在原业务事务内先取消其他默认标记并 flush，再设置目标并 flush，避免 ORM 主键排序造成临时冲突。创建默认账号先插入非默认账号；普通编辑中的 `is_default=true` 延后执行切换。切换、其他配置修改和审计仍由调用方统一提交，失败可整体回滚，没有新增提前 commit。

行版本冲突返回 `409 / DRIVE_ACCOUNT_CONFLICT`，默认唯一约束冲突返回 `409 / DRIVE_ACCOUNT_DEFAULT_CONFLICT`，均提示刷新重试，不自动重放其他业务修改。直接 SQL 也受数据库唯一索引约束。

回滚测试还复现了凭据 expire 清理钩子在 ORM 对象已经被回收时收到 None 的问题；改用原始 InstanceState 清理 pending 字段，避免回滚异常覆盖原始冲突。

## 资料时间

增加独立可空列 `profile_updated_at`。网盘成功返回可保存资料时，在 IO 阶段记录其完成时间，结果实际写回时同步保存。认证成功但资料刷新失败、初始化失败或没有资料返回时，保留旧资料和原资料时间；`last_checked_at` 仍记录探测时间。批量刷新不会把较早取得资料的时间伪装成整批完成时间。

两类时间均显式使用 UTC 写入，API 按现有规则转成北京时间，避免 Docker 配置非 UTC 时区后重复偏移。已经完成短信认证的光鸭兼容路径若保存新身份资料，也会记录该次资料写入时间。

## 迁移

新增 Alembic revision `20261116_default_profile_time`，前置为 `20261116_account_row_version`。升级时：

1. 新资料时间列对历史行保持 NULL，不用可能对应失败探测的 last_checked_at 猜测成功时间；原资料内容保留，待下一次成功刷新再填写。
2. 若旧库已有多个默认账号，按现有默认账号列表的 id 顺序保留最小 id，清除其余默认标记，并递增受影响行的版本；不改变凭据。
3. 创建部分唯一索引。

停写并备份后升级到 head，再启动新版。应用已启用启动迁移的部署沿用原有流程；关闭自动迁移的部署需显式升级。降级只移除新增索引和时间列，不恢复原有重复默认标记，也不还原已递增的行版本。此次未在真实数据库执行迁移。

## 验证

专项回归覆盖旧快照并发切换、直接 SQL 约束、向较小 id 切换、已有默认时创建与编辑、默认切换与凭据修改共同回滚、成功/失败资料时间、未知历史时间、非 UTC 主机时钟，以及真实 Alembic 在有重复默认的隔离库升级、降级再升级和账号表列/类型/索引漂移检查。
