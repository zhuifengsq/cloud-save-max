# 第三轮后端复审整改

本轮修复日志异常明文、账号探测结果不一致及账号网络操作跨数据库事务的问题，同时扩大静态门禁。没有读写真实数据库、真实 keyring 或网盘，没有提交代码。

## 日志边界

- 适配器捕获异常后记录操作及异常类型，不记录原始异常字符串或原始 traceback；覆盖 86 处相关表达式替换。123 网盘的传输异常返回安全消息，防止经响应摘要再次进入日志；其摘要不再记录上游 message。部分认证失败、任务查询日志也移除原始响应或上游文案。
- 默认控制台改用 `SafeFormatter`：URL 去掉 userinfo、查询内容和 fragment；常见认证字段、Cookie、token、移动端参数脱敏；异常保留堆栈文件/行号/函数和类型，去掉异常正文及源代码行。格式化使用 LogRecord 副本，不改变其他处理器收到的记录。
- 格式化是输出防线，不能识别任意无标签字符串。新增或自定义处理器也应使用安全格式化；业务代码仍需避免记录原始凭据、请求体和响应体。未声称历史日志已清理。

## 账号状态与事务

- 探测分成账号快照、无事务网盘操作、版本校验及结果写回。Factory 构造、初始化、导出配置、资料读取、签到均在释放调用方读事务后执行。写入和审计仍由原调用方提交；失败或 rollback 不会提前保存候选凭据。
- 初始化失败继续累计失败次数，连续三次仍禁用；初始化成功但资料/配置刷新抛异常时保持 active，保留已知资料、保存可用的刷新配置并提供安全错误提示，不把资料接口故障当作认证失败。需要图片/短信验证的异常仍进入认证流程；保留光鸭短信认证已完成时的兼容处理。
- 批量资料刷新先完成全部网盘 IO，再在同一业务事务内应用结果；不会在每个账号之间自动提交。发生账号版本变化或删除时拒绝旧结果，最终 mapper 条件写入继续防止检查后的竞争。
- 只读释放前检查未提交的新增/修改/删除、已 flush 的业务写入及通过 Session.execute 发出的写语句，发现写入即拒绝，不以提前提交业务数据来缩短事务。直接从底层 Connection 发出的 SQL 不在 Session 追踪边界内，不用于这些账号入口。

## 二次认证

网页和 Telegram 的扫码、验证码、短信流程改成候选配置传入探测，取消“先 update/flush 再联网”。认证会话记录账号 row_version；第一次提交/轮询网络请求前验证版本，请求后的候选配置和探测结果继续使用同一版本校验。账号被编辑或清除凭据时，旧会话及在途结果返回冲突，不能覆盖新配置。

认证准备只读账号身份和版本，不要求已有有效凭据；清除阿里云 refresh token 后仍能开始扫码恢复。会话版本为进程内字段，本轮不新增数据库迁移。

## 门禁与部署边界

Ruff 从 F6/F7/F82 扩大为 F6/F7/F8，增加重复定义、未使用局部变量等检查，修复 35 项原有诊断；配置保存、任务调度、清理等有副作用的调用保留，正则编译验证保留。mypy strict 从 16 文件扩大到 22，新增日志、脱敏、凭据封装、公开资料、登录请求体限制和账号操作数据结构；没有通过全局 ignore 放行错误，也没有宣称全仓类型覆盖。

容器 Uvicorn 显式 `--workers 1`，避免 `WEB_CONCURRENCY` 意外增加 worker。登录限流、缓存、二次认证会话和后台调度仍按单实例设计，未引入 Redis 等共享状态或多实例调度协调。凭据加密仍沿用已有独立 keyring 与显式迁移方案，兼容模式不会自动变成强制加密；本轮没有生成或替换真实运行密钥、转换真实旧库。

## 验证方法

回归先观察旧行为失败再验证修复：资料异常和真实初始化异常分流、全部网盘阶段无事务、候选配置 rollback、已 flush 的写入拒绝、批量刷新、网盘 IO 期间并发修改、图片/短信/光鸭/扫码真实 API 路由及提交期间的并发变化、清除凭据后的认证准备、过期版本会话拒绝、Quark/UC 的假传输异常、Pan123 异常经登录响应摘要的第二次传播、默认格式化输出及异常堆栈脱敏。

测试固定 `XXM_TESTING=1 DATABASE_URL=sqlite:// RUN_MIGRATIONS=0 SCHEDULER_ENABLED=0`，清除进程内实际 keyring 环境变量，使用临时 SQLite、假密钥和模拟网盘 IO。未执行真实 CI、Docker 启动或代理链验收。
