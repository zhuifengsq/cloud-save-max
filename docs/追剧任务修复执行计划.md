# 追剧任务的 18 项问题与修复执行计划

适用仓库为 `cloud-save-max`。审查日期为 2026-11-25。目标是防止漏集、误转、错误停用和进度回退，让预览、实际写入和任务记录给出一致的结果。

## 给 Codex 的执行指令

> 请在本仓库按 A 至 F 的顺序实现下列 18 项修复。先对照当前分支和现有测试逐条复核，再用能复现问题的最小回归测试推动修改。如果当前版本已经修好某项，用对应测试证明并记录。每组完成后运行相关测试，最终按编号报告修改文件、测试结果和仍需真实网盘验证的部分。使用临时 SQLite、固定时钟和模拟网盘响应进行验证。

后端为 Python、FastAPI、SQLAlchemy 和 APScheduler，前端为 Vue 与 TypeScript。下文路径相对仓库根目录。验收应经过实际使用该逻辑的入口，例如从任务更新接口读回数据库状态、从执行记录核对成功或待确认状态。各项均可独立记录进度。优先完成 A、B 两组；F 组的并发工作依赖前面各组的状态隔离和恢复语义。

审查时选取的相关测试合计后端 782 项、前端 61 项通过。问题来自额外本地样例或调用链检查；串行调度的影响属于代码分析，真实网盘耗时尚未测量。旧文档 `docs/追剧任务执行链路优化评估.md` 包含历史快照，引用时以当前实现为准。

## A　确保成功状态与网盘结果一致

- [ ] **01　字幕被当成同集正片。** 普通模式把目标目录所有可识别季集号的文件都加入已存集号集合。修复 `backend/app/infrastructure/execution/drama_plan.py` 的 `build_transfer_plan`，区分正片和字幕、元数据等附属文件。先做文件类型判断，再做跨文件名的季集判重。与第 09 项共用类型判断，避免开启忽略后缀时再次被字幕挡住。**验收**：仅有 `Series.S01E05.srt` 时，同集 MKV 入选；已经有同集正片时继续判重；严格和忽略后缀两种设置都覆盖。

- [ ] **02　来源分页不完整仍可能成功并停用。** 夸克声明共 2 项，第一页返回 1 项，第二页为空；如果已返回的那集在目标中，普通模式会得到空计划。修改 `backend/app/infrastructure/drive/adapters/quark_adapter.py` 的 `get_detail` 和 `backend/app/infrastructure/execution/drama_executor.py` 的分享清单读取路径，区分完整空目录、部分清单和读取失败。普通扫描以及增量根目录和子目录均要传递完整性结果，保留显式仅取首页的调用契约。**验收**：上述输入产生可重试的非成功状态，一次性任务仍启用；补全第 2 页后只补缺集；总数为 0 的完整空目录维持原有行为。对缺少总数字段的其他网盘按各自分页契约判断。

- [ ] **03　非夸克重命名失败仍报成功。** `drama_executor.py` 的 `_execute_normal` 忽略 `_rename_by_fids` 的校验结果。让已确认、明确失败和结果未知分别进入对应状态；只记录可核实的新名字，保留已经转存的事实。重试应优先按已知文件 ID 核对或改名。**验收**：模拟转存成功后改名被拒绝、校验读取超时、改名成功三种响应；从 `backend/app/infrastructure/execution/task_executor.py` 核对执行状态、结果树、已存进度及一次性开关。前两种仍启用，恢复时不重复提交已确认文件。

- [ ] **04　不同任务可以串用剧名。** `backend/app/infrastructure/execution/magic_rename.py` 的 `set_taskname` 会修改实例共享的变量字典。让每个重命名器拥有独立的任务名及可变覆盖值，保留现有内置规则和自定义覆盖。**验收**：创建 A、B 两个实例，依次设置不同剧名，再交错调用含 `{TASKNAME}` 的替换。A 始终输出 A，B 始终输出 B；普通实例与带自定义变量的实例都测。

## B　防止旧状态或旧预览写回

- [ ] **05　旧编辑页回退进度并重新启用一次性任务。** `frontend/src/components/tasks/DramaTaskDrawer.vue` 会提交打开抽屉时复制的整份状态；`backend/app/application/tasks.py` 的 `update_task` 接受其中的 `saved_latest` 和 `enabled`。让前端 PATCH 只提交实际修改的字段，后端保护执行器维护的进度、分享记录和换链日志；显式启停和手动校正仍走其支持的入口。**验收**：打开第 8 集且启用的任务，模拟后台写成第 10 集并自动停用，只修改任务标题再保存。重新读取应为新标题、第 10 集、已停用。补测旧客户端提交完整表单的情况；以版本检测或明确冲突处理过期的启用状态。

- [ ] **06　引流确认可能写入预览之外的文件或目录。** `backend/app/application/use_cases/task_lead_in.py` 的预览令牌已有目录和素材 ID；确认阶段按路径重新解析后，应在调用任何添加方法之前核对网盘稳定 ID，并按各驱动支持的字段核对素材身份。在已有锁内完成核对，发现替换时复用已有的预览过期响应。**验收**：分别模拟同路径素材被同名新文件替换、同路径目标目录重建；确认返回过期，模拟适配器的添加调用次数为 0。原文件、原目录正常确认，重复确认继续查重。

## C　让普通模式的预览和执行使用同一套文件规则

主要入口为 `backend/app/application/share_preview_plan.py` 的 `plan_preview_items`、`backend/app/infrastructure/execution/drama_plan.py` 的 `build_transfer_plan`，以及 `drama_executor.py` 的 `_filter_transfer_files`。复用纯函数处理候选和判重，预览保留过滤原因，执行保留网盘令牌及确认逻辑。用同一组输入同时断言预览结果和实际计划。

- [ ] **07　修改日期过滤只在预览生效。** 将预览已有的日期解析与边界比较用于实际文件筛选；目录整包路径遇到文件级时间规则时，应进入可逐文件检查的路径。**验收**：设下限 `2026-01-01`，2024 年文件被排除，边界当天文件入选。秒、毫秒时间戳和当前支持的日期字符串得到一致结果，缺失日期沿用已确定的预览语义。
- [ ] **08　正则未匹配的文件仍被转存。** 普通模式生成重命名目标前，应像预览一样先检查源文件名是否匹配。**验收**：模式 `^Show`、替换 `Series`，`trailer.mp4` 在两个入口均被排除，`Show.mp4` 均得到 `Series.mp4`；空模式以及内置规则仍按各自契约处理。
- [ ] **09　目标已有特辑仍会重复提交。** 把候选的最终目标名与现有目标文件按相同规则判重，同时保留源文件名判重及同批冲突裁决。与第 01 项一起区分正片与附属文件。**验收**：开启忽略后缀，目标有 `Special.mp4` 时跳过 `Special.mkv`；严格模式下这两个无集号视频可区分；将 `Raw.mkv` 改名为已存在的 `Final.mkv` 时，严格模式也应跳过。断点中已经确认的源文件继续参与现有的恢复判断。

## D　让自动换链保留选中的内容与访问参数

主要入口为 `backend/app/application/share_listing.py` 的 `ShareListingReader` 和 `backend/app/application/drama_share_autoupdate.py` 的 `resolve_drama_shareurl_update`。验收同时检查更新后的链接经适配器解析得到的目录、分享标识和提取码。

- [ ] **10　文件夹对比模式会选回已排除目录。** 候选已按规则筛出可用文件组，最后一次根目录重选却可能定位到另一分支。让最终定位只取通过筛选的分支或其符合目录结构要求的祖先。**验收**：根目录顺序为「预告」「4K 正片」，剧名均未出现，设置包含 4K、排除预告，应定位到正片分支。没有合格分支时保留原链接。
- [ ] **11　夸克分享根目录平铺的正片被漏掉。** `ShareListingReader.groups` 应为根级文件生成可选文件组。普通模式选中该组时保持根目录定位，并区分“选中根目录”和“没有文件组”。**验收**：根目录只有两集、无子目录，换链成功且两集可进入普通计划；根与子目录都有文件时，两处候选均可见；保留现有带子目录定位的链接语义。
- [ ] **12　普通模式的目录优先级输给文件数量。** `_pick_fid_for_normal_mode` 只按数量、更新时间比较。保留优先关键词匹配结果，先比较是否命中优先级，再在同级内比较数量和时间；沿用任意或全部关键词设置。**验收**：已设置 4K 优先时，1 个 4K 正片胜过 6 个普通预告；清空优先设置后继续按现有数量和时间规则选择。
- [ ] **13　百度改写子目录可能丢提取码。** `_rewrite_shareurl_with_fid` 直接移除片段，而 `backend/app/infrastructure/drive/adapters/baidu_adapter.py` 可从片段读取四位提取码。按网盘格式改写链接，使提取码能与目标目录共存，保留已有查询参数。**验收**：分别输入片段形式和查询参数形式的提取码，增设、更换、清除目录定位；对改写前后结果调用百度适配器的 `extract_url`，分享标识和提取码保持一致，目录指向期望位置。回归夸克和移动云盘已有定位格式。

## E　校准任务进度、配置和运行日期

- [ ] **14　跨季进度只比较集号。** 修改 `backend/app/infrastructure/execution/drama_progress.py` 的 `calculate_saved_latest`。对于两条都有明确季号的记录，按季号、集号顺序比较；为无季号文件、目录提示和历史水位保留明确的兼容策略。**验收**：`S01E24` 与 `S02E01` 任意顺序输入都返回第二季第一集；旧水位是第一季第 24 集时也能推进。检查自动记录、手动校正以及 `backend/app/application/drama_update_progress.py` 返回给任务页的进度。
- [ ] **15　更换目标目录或账号后继承旧进度。** 在任务更新事务中，当有效保存目标变化时失效旧的 `saved_latest`，下次扫描用新目标重建。与第 05 项配合，旧表单不能重新写入它。**验收**：原目标第 8 集，改到空目标后读取为暂无已存进度；新目标只有第 2 集时显示第 2 集；只改标题仍保留旧水位。已有对外分享记录的失效逻辑继续生效。
- [ ] **16　编辑时可保存无法识别的分享链接。** 在 `backend/app/application/tasks.py` 中复用创建任务的网盘识别规则。更新给出新链接时，先校验再修改任务、追加成功日志；只改无关字段时兼容已有记录。**验收**：通过 PATCH 提交空串或 `incorrect-link` 应得到参数错误，重新读取得到原链接，成功日志数量不变；受支持的有效新链接正常保存。
- [ ] **17　Cron 与运行星期可能采用不同的时区。** `backend/app/infrastructure/scheduling/task_scheduler.py` 用配置时区触发，执行器取宿主本地时间判星期。让定时任务准备阶段把同一时刻按有效调度时区转换，再交给 `backend/app/application/drama_schedule.py`；列表和详情的“今天”采用同一口径。保留手动触发的日期豁免及配置性拦截。**验收**：固定 `2026-11-24T16:05:00Z`，时区为上海、只跑周三时应执行；同一瞬间设置 UTC 应按周二判断。复测默认配置和一次性任务。

## F　缩短慢任务对其他账号的阻塞

- [ ] **18　定时任务串行等待网盘。** `run_drama_tasks` 按任务 ID 同步执行。先用两个独立账号的模拟适配器建立基线，让 A 停在确认阶段并记录 B 的启动时刻。然后采用有界并发，复用 `backend/app/infrastructure/scheduling/task_admission.py` 的全局容量和同任务互斥。优先让不同账号并行，同一账号或同一保存目标采用保守顺序；每个工作线程独立使用数据库会话，批量通知由协调线程汇总。**验收**：用事件控制线程，A 尚未释放时 B 已启动；同任务不会被手动与定时重复执行；容量占满时任务去向可追踪；单个任务抛错能释放槽位；一轮结束后通知不重不漏。用模拟计时与调用记录说明改进，真实网盘吞吐量单独报告。

```powershell
Push-Location backend
try {
    $auditTemp = Join-Path (Resolve-Path .tmp) ('drama-fixes-' + [guid]::NewGuid())
    & .\.venv\Scripts\python.exe -m pytest -q --basetemp $auditTemp tests regression_tests
    if ($LASTEXITCODE -ne 0) { throw '后端回归失败' }
} finally { Pop-Location }

Push-Location frontend
try {
    $cases = @(Get-ChildItem regression_tests -Filter '*.test.mjs' | ForEach-Object FullName)
    node --test @cases
    if ($LASTEXITCODE -ne 0) { throw '前端回归失败' }
} finally { Pop-Location }
```
