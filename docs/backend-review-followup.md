# 2026-11-16 第二轮复审修复

本轮落实重新审查确认的五项问题，并补齐独立复核发现的签到审计、后台通知错误旁路。没有操作真实数据库、网盘或密钥，也没有提交代码。

## 行为变化

1. 账号资料仅保存允许的基础字段和标量值，`raw`、未知字段和嵌套对象不会写入 `profile_json`。应用层与 ORM 写入边界共用白名单；账号错误不保存原始异常字符串。签到失败响应、失败审计和后台探测通知使用安全文案或错误码，不带上游原始 message/reward/异常文本。
2. `drive_accounts.row_version` 为 ORM 乐观锁。旧 Session 的编辑、探测、令牌写回或删除遇到较新版本时失败，HTTP 返回 `409 / DRIVE_ACCOUNT_CONFLICT`，提示刷新重试；不会自动重放网盘操作。后台探测遇到版本冲突会丢弃旧结果，不修改新账号状态、不发送失效通知。账号 ORM 批量 UPDATE/DELETE 被拒绝，避免绕过加密、资料白名单与版本条件；维护用 Core SQL 不在此保护范围内。
3. 预览对 token 与详情响应校验 code/status、data 和 list 结构。合法空列表可以成功；错误响应和畸形结构会尝试其他账号。临时网络、账号认证、提取码及未知错误不进入内存或数据库负缓存，也不写失效链接表。只有适配器明确分类、匹配已登记的失效码，且全部候选账号一致确认失效，才持久化失效结果。上游原始错误消息不会返回客户端。
4. 历史自由文本负缓存不再直接用于拒绝探测，仅复用新版的明确失效标记。未知网盘错误保守地按可重试故障处理，不能据此认定链接永久失效。
5. 登录用户名最多 64 字符、密码最多 4096 字符，超长字段返回安全的 400；解析表单前限制实际请求体 16 KiB，超限返回 413，适用于无 Content-Length 的请求。限流组合键使用 SHA-256 用户名摘要，避免长期保留原始长字符串。普通登录、刷新、注销和已有 429 行为保留。

## 部署与历史数据

新增 Alembic revision `20261116_account_row_version`，接在凭据加密列迁移之后。部署时停止旧实例和后台写入，升级到 head 再启动新版；关闭自动迁移的部署必须显式执行 Alembic 升级。旧进程不会遵守新版本锁，不能混用来保证并发保护。

历史账号资料与 `last_error` 清理由现有显式命令 `scripts/migrate_credentials.py` 处理。即使账号已是 v1 且未指定 `--rotate`，也会清理资料和错误旁路；重复执行无变化时计数为零。仍要求独立 keyring、停写和新的备份路径，不会在启动时自动转换真实凭据。已有备份、SQLite 空闲页和 WAL 可能保留历史明文，逻辑更新不等于物理擦除。

历史 `request error` 误判有独立工具，以下在仓库根目录运行，先将路径替换为明确选定的数据库路径：

```powershell
# 默认只读统计，不创建数据库，不输出链接或错误内容。
backend/.venv/Scripts/python.exe scripts/repair_preview_failures.py --database <数据库路径>

# 停止应用写入后，先备份并验证，再删除已知错误记录。
backend/.venv/Scripts/python.exe scripts/repair_preview_failures.py --database <数据库路径> --apply --backup <新的备份路径>
```

工具只删除消息等于 `request error` 或以 `: request error` 结尾的失效记录和失败缓存，保留成功缓存、明确失效及未知错误记录；不猜测或批量清空其他历史记录。运行后重启进程以清空旧版内存缓存。本轮只在假数据库中验证了此命令。
